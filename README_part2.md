# Часть 2: система масок + интерактивная карта

Один пайплайн с набором масок вместо трёх параллельных методов из части 1,
плюс веб-приложение: карта с выбором региона/показателя, слоями и **живым
пересчётом распределения по весам масок**.

## Маски

Каждая маска даёт ячейке вес 0..1 по одному признаку. Итоговое распределение —
взвешенная сумма масок, нормированная на региональное значение (сумма по ячейкам
сохраняется). Все маски лежат в `src/masks/`.

**Композиционные (считаются по атрибутам сетки в ETL):**

- `baseline.py` — равномерно по площади ячейки
- `worldpop.py` — пропорционально населению (WorldPop 100 м)
- `regression.py` — log-регрессия на 87 регионах; эластичность гор. населения
  1.39 (НИОКР) / 2.77 (отгрузка): `вес = население^эластичность`
- `distance_to_city.py` — `exp(-d/σ)`, σ=10 км
- `distance_to_center.py` — `exp(-d/σ)`, σ=30 км

**Инфраструктура и территория (считаются оффлайн по OSM, грузятся как слой-маски):**

- `road_network.py` — близость к дорогам по классам (федеральные motorway/trunk,
  региональные primary, местные secondary); считается в PostGIS (KNN)
- `road_traveltime.py` — время в пути по дорожной сети до ближайшего города
- `railway.py` — близость к ЖД-узлам (station/halt/yard)
- `power.py` — близость к ЛЭП (power=line)
- `territory.py` — тип территории по OSM landuse (промзона 1.0 … вода 0.0)

Оффлайн-расчёт (нужен `osmnx`, зеркало Overpass mail.ru) — скрипты
`scripts/compute_traveltime.py`, `compute_infra_masks.py`, `compute_territory.py`;
результаты кэшируются в `data/processed/*.csv` и `graphs/*.graphml`, ETL грузит
готовое (slim-образ ETL без osmnx).

## Композиция и живой пересчёт

`src/masks/composition.py`: взвешенная сумма, мультипликативное гейтирование,
энтропийное сглаживание — сумма по ячейкам сохраняется.

Базовые веса: regression 0.5, worldpop 0.3, distance_to_city 0.1, distance_to_center 0.1.

На фронте веса любой маски крутятся слайдерами; по кнопке «Пересчитать» уходит
`POST /api/recompute`, и распределение пересчитывается **на лету** функцией
PostGIS `tile_composition` (`value = (Σ вес·маска)·региональное/нормировка`),
с пересчётом метрик (Джини, top-10%). Пресеты весов (бывшие ablation-конфигурации)
заполняют слайдеры стартовым набором.

## Веб-приложение

Стек (см. `docker-compose.yml`):

- **db** — PostGIS: сетка, веса масок (`mask_cell_value`), композиции, города, дороги
- **etl** (`etl/ingest.py`) — загрузка всего в БД (идемпотентно по региону)
- **tiles** — Martin: векторные тайлы из функций PostGIS (`tile_mask`,
  `tile_distribution`, `tile_city`, `tile_road`, `tile_composition`)
- **api** (`apps/api`, FastAPI) — справочники (`/api/regions|indicators|masks`)
  и живой пересчёт (`/api/recompute`)
- **web** (`apps/web`, React + MapLibre) — карта: регион/показатель, слой
  распределения, маски (наложение), города и дороги, пресеты + живой пересчёт,
  мини-карта-локатор с подсветкой региона

### Запуск локально

```
cp .env.example .env          # при необходимости поменять порты
docker compose up -d db tiles api web
docker compose run --rm etl   # разовая загрузка данных в БД
```

Открыть `http://localhost:${WEB_PORT}` (по умолчанию 5173). Данные масок уже
посчитаны и лежат в `data/processed/` — Overpass повторно не вызывается; для
пересчёта с нуля есть `scripts/compute_*.py`.

### Развёртывание

Helm-чарт `deploy/helm/spatial-masks` (db/api/web/tiles/ingress + Job-хуки на
миграции и ETL). Миграции схемы — `deploy/helm/.../files/migrations/*.sql`
(применяются pre-upgrade хуком). CI `.gitea/workflows/build-deploy.yaml`:
push в `main` → сборка образов → `helm upgrade`. Демо: deaggr.kravchenko.cloud.

## Ограничения

- **Муниципальных данных нет** → обратная агрегация и holdout не сделаны
  (parquet Росстата — только уровни Регион/Федокруг/Страна)
- CV регрессии нестабильна, R² 0.62 ± 0.22
- **Тип территории** ограничен полнотой OSM landuse (покрытие ячеек: МО ~60%,
  Краснодар ~51%, Якутия ~18%; вне тегированных полигонов вес 0)
- Инфраструктурные/территориальные маски пока **слой + живой пересчёт**, в
  «эталонную» композицию из ТЗ ещё не зашиты
- Не реализовано: VIIRS (ночная засветка), базовые станции, ML+F1-бенчмарк
